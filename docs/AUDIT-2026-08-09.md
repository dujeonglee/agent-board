## Executive Summary

board는 견고한 라이프사이클 규율을 갖췄다 — 삭제 좀비-워크스페이스 레이스 봉합(SIGKILL 에스컬레이션), Router 파리티 계약, atomic status write, singleton flock, post_id 파생으로 traversal 소멸. **과거 봉합은 전부 회귀 없이 건재**(아래 재검증 참조). 이번 신규 발견의 무게중심은 **보안 기본값**과 **cli와의 경계 계약**이다:

- 두 P0가 곱해진다 — 무인증 기본 배포(B-1)가 API 키 유출 SSRF(B-2)를 원격 무인증으로 만든다.
- board↔cli 경계가 가장 큰 구조 리스크 — board가 cli의 private 심볼을 import(B-12)하고 on-disk 포맷을 픽스처로만 검증(B-13).

## Findings

### [P0] B-1 · 기본 배포가 모든 인터페이스에서 완전 무인증
`config.py:64` (`gateway=board-proxy`) · `app.py:593` (`host=0.0.0.0`) · `app.py:243`
- **Impact**: board-proxy 모드엔 미들웨어·`Depends`·토큰 체크가 전무. LAN/VPN의 누구나 `POST /api/posts`(spawn)·`DELETE`(kill+rmtree)·`/admin` 도달. 설계의 "네트워크 격리" 전제를 출하 기본값이 스스로 위반. caddy 모드 비-loopback 경고(`app.py:609`)는 있으나 board-proxy 경로엔 없음.
- **Fix**: 기본 host를 `127.0.0.1`로. board-proxy + 비-loopback 바인드는 명시적 opt-in 없이는 **하드 에러**로 거부. 또는 board 레벨 basic-auth 옵션. → **경계 A** 참조(cli와 조율 필요).

### [P0] B-2 · admin API가 공격자 지정 URL로 API 키 유출(SSRF)
`admin.py:114-144` (`list_served_models`) · `PUT /api/admin/config` (`app.py:330-336`)
- **Impact**: `base_url`를 설정 가능하고, models 조회/detect가 **실 저장 API 키**를 `Authorization: Bearer`(`admin.py:130`)/`x-api-key`로 그 URL에 전송. GET config는 키를 마스킹하지만 프로브는 실제로 *보냄*. B-1과 결합 시 무인증 원격 유출 + 내부망 SSRF.
- **Fix**: 임의 base_url에 자격증명 동봉 금지 — 프로브를 allowlist/loopback로 제한하거나 재확인 요구. `base_url` 변경을 특권 동작으로.

### [P1] B-3 · stale/재활용 pid를 kill(무관한 프로세스 종료 가능)
`instances.stop_instance:145-163` · `pid_alive:100-130`
- **Impact**: `web.json`의 pid를 `pid_alive` 체크만으로 kill. SIGKILL된 인스턴스의 web.json은 정리 안 됨 → OS가 pid 재활용 시 무관한 프로세스에 시그널. workspace-파생 가드는 *재활용* pid는 못 막음.
- **Fix**: 시그널 전 pid의 start-time/cmdline을 spawn 시 기록값과 대조.

### [P1] B-4 · restart / change_model이 SIGKILL 에스컬레이션 없이 stop
`orchestrator.py:140, 174` → `stop_instance(wait_s=0.0)`
- **Impact**: 삭제 경로는 `wait_s=8.0`로 수리됐지만 restart/change_model은 기본 `0.0` — SIGTERM만, 대기·SIGKILL 없음. `_await_dead`는 관찰만 하다 타임아웃 후 살아있는 구프로세스에 재attach. "새로 설치한 agent-cli 반영"이 wedged 인스턴스에 조용히 no-op.
- **Fix**: 이 경로들도 `wait_s` 에스컬레이션 stop을 거쳐 respawn.

### [P2] B-5 · Caddy /s/<id> 인증이 두 설정의 합치에 의존(우회 풋건)
`router.py:299-333` · `deploy/Caddyfile`
- **Impact**: 동적 라우트는 `caddy_basic_auth` 설정 시에만 인증 핸들러 임베드, 그리고 `routes/0`에 삽입돼 사이트 `basic_auth`보다 앞섬. Caddyfile엔 auth 있는데 env 잊으면 인스턴스 라우트가 먼저 매치돼 사이트 인증 우회.
- **Fix**: 두 자격증명을 단일 소스에서 파생, 또는 사이트 auth 존재 시 env 비면 라우트 등록 거부.

### [P2] B-6 · SQLite busy_timeout 미설정 · orchestrator set_session_id 미가드
`store.py:64-66` · `orchestrator.py:106`
- **Impact**: WAL은 켰으나 `busy_timeout` 없고 단일 커넥션을 executor 스레드 공유. 첫 open의 `set_session_id`는 `create_post`와 달리 try/except 없어 UNIQUE 충돌이 500.
- **Fix**: `PRAGMA busy_timeout=5000`, orchestrator `set_session_id`를 try/except.

### [P2] B-7 · /api/posts가 이벤트 루프 스레드에서 뷰 구성(블로킹)
`app.py:385-389` · `_post_view app.py:184`
- **Impact**: `list_posts()`는 executor 오프로드했지만 `[_post_view(p) …]`는 루프서 인라인 — 동기 파일 read·`pid_alive`(ps 서브프로세스)·구버전 블로킹 `httpx.get /health`. 매 대시보드 load/재접속마다 전 글에 대해 루프 블록.
- **Fix**: 뷰 구성 전체를 executor로 오프로드. (⚠️ cli 세션 포맷 의존 — **경계 B** 단방향)

### [P2] B-8 · pid_alive가 라이브 글·스캔틱마다 ps 서브프로세스 fork
`instances.py:116-121` · `live_events.py:76` (interval=1s)
- **Impact**: N개 라이브 인스턴스에 초당 `ps` N회 fork — 지배적 헬스체크 비용.
- **Fix**: `/proc/<pid>/stat`(Linux) 읽기, 스캔틱 내 liveness 캐시.

### [P2] B-9 · last_query가 매번 history.jsonl 전체 read+split
`sessions.py:33-42`
- **Impact**: 마지막 user 쿼리 하나 얻으려 전 파일 메모리 적재+`splitlines()` — 글당·스캔당. 대화 길이에 비례 성장.
- **Fix**: tail(마지막 N KB) 또는 mtime 키 캐시. (⚠️ cli history.jsonl 포맷 의존 — **경계 B** 단방향)

### [P2] B-12 · admin이 agent-cli의 private 내부 심볼을 import  🔗경계
`admin.py:236` (`_detect_runtime_capabilities`) · `:219` (`list_names`)
- **Impact**: `_`-prefix private 함수를 import — 별도 버전 관리되는 패키지의 불안정 내부 API에 결합. agent-cli 리네임 시 컴파일타임 신호 없이 admin detection 파손(`ImportError` 폴백뿐).
- **Fix**: **fix가 두 저장소에 걸침** — agent-cli가 capability detection/wire-format names의 *공개* API를 노출하도록 요청, board는 그것을 소비. → **경계 B** 참조.

### [P2] B-13 · board↔cli on-disk 계약이 픽스처로만 검증 · 런타임 버전 단언 없음  🔗경계
`sessions.py` · `instances.py` · `clone.py` · DESIGN §7/§14
- **Impact**: board가 `web.json`/`status.json`/`history.jsonl`/`session.jsonl` 포맷을 직접 파싱·*기록*(clone이 `_meta` 재작성). "통합 계약"이나 실 agent-cli 아닌 테스트 픽스처로만 검증 → 포맷 드리프트가 런타임에 조용히 degrade. DESIGN §14 버전 의존을 런타임서 아무도 체크 안 함(`cli_version` 존재하나 미비교).
- **Fix**: 실 agent-cli(또는 golden 파일) 계약 테스트 추가, `cli_version` < 최소치면 경고 로그. → **경계 B** 참조.

### [P3] B-10 · /api/events 무제한 per-subscriber 큐(메모리 DoS)
`live_events.py:41-56` · `app.py:410-431`
- **Impact**: `subscribe()`가 무제한 `asyncio.Queue`, `put_nowait` 브로드캐스트. 안 읽는 slow-loris가 무한 누적, 구독자 수 상한 없음(B-1 무인증과 결합 시 자명 도달).
- **Fix**: 큐 bound(drop-oldest), 동시 구독자 cap.

### [P3] B-11 · clone이 복사 트리 내부 심링크 역참조
`clone.py:118-128` (`copytree symlinks=False`)
- **Impact**: `_safe_join`은 선택 rel경로의 `..`만 막고, `copytree`는 디렉토리 내부 심링크를 역참조 → 워크스페이스 밖 타깃 내용이 새 워크스페이스로 복사.
- **Fix**: `symlinks=True`로 링크 보존, 또는 밖으로 resolve되는 심링크 거부.

## 🔗 경계 (agent-cli ↔ agent-board) — 두 저장소에 걸친 종속 항목

> 이 섹션은 **양쪽 문서에 공통**. 나머지는 각 저장소 전용.

### A. 보안 노출은 단일 공격면 (완화가 조율돼야 함)
board-proxy는 cli 인스턴스에 **loopback으로 중계**하고, cli는 `--trust-local`로 loopback 요청의 토큰을 스킵한다. 따라서 board의 인증 부재(**B-1**)가 그대로 cli 인스턴스의 노출이 된다. 한쪽만 잠그면 우회 가능:
- board만 loopback 잠금 + cli 인스턴스 포트(50000–60000)가 직접 도달 가능 → board 우회로 cli 직격
- cli만 loopback + board가 `0.0.0.0` → board-proxy가 여전히 중계

→ **B-1·B-2**(board)와 **C-4·C-5·C-11**(cli)는 **함께** 완화해야 온전. 두 저장소 동시 작업.

### B. 경계 계약의 수정이 양쪽 코드를 건드림
- **B-12**: board가 cli의 private `_detect_runtime_capabilities`/`list_names`를 import → fix는 **agent-cli가 공개 API를 노출**해야 완결(cli 변경 필요).
- **B-13**: board가 cli on-disk 포맷(`status.json`/`web.json`/`history.jsonl`/`session.jsonl`)을 파싱·기록 → 계약 테스트는 **실 agent-cli(또는 golden)** 필요, 버전 단언은 양쪽 합의.
- 단방향: **B-7·B-9**도 cli 세션 포맷에 의존하나 수정은 board측(포맷 변경 시 깨지는 리스크만 공유).

## 과거 버그 재검증 — 회귀 없음 (세션 기록 대조)

- **삭제 좀비-워크스페이스 레이스** — `stop_instance(wait_s=8.0)`가 폴링 후 SIGKILL 에스컬레이션, rmtree 전 `workspaces_root` prefix 재검증. 봉합 건재.
- **base-path 검증 후 kill** — post-파생 워크스페이스의 web.json pid만 대상(잔여 리스크는 pid 재활용 = B-3).
- **status.json tmp 레이스** — `mkstemp` 유니크 tmp + `os.replace`(admin/fsio). 정상.
- **Router 파리티** — 순수 ABC(공유코드 0) + parametrize parity 테스트.
- **프록시 SSRF 없음** — upstream URL은 항상 `127.0.0.1:<board-controlled port>`.
- **traversal** — post_id는 uuid4라 `../` post_id는 fs 접촉 전 404. 삭제는 `workspaces_root` prefix 재검증.

## 프로세스 위생 (감사자 직접 확인)

- **버전 2중 소스** — CLI는 `dynamic=["version"]`+`attr`로 단일화했으나 board는 `pyproject.toml`과 `__init__.py`에 `1.24.0`을 이중 관리(과거 slow-open 사가의 함정). CLI와 동일하게 `attr` 파생으로 단일화 권장.
- **CHANGELOG 문서 부채** — board는 1.24.0인데 최신 항목 1.22.1 — 실제 버전에 뒤처짐. 1.23.x/1.24.0 소급 정리 필요.

## 권장 조치 순서 (board)

1. **보안 기본값 잠금** — host `127.0.0.1`화 + board-proxy 비-loopback 하드 에러(B-1), admin `base_url`→키 프로브 제한(B-2). → **경계 A**로 cli(C-4·C-5)와 동시.
2. **프로세스 수명 봉합** — restart/change_model에 SIGKILL 에스컬레이션(B-4), pid 정체성 확인(B-3).
3. **경계 계약 강화** — cli 공개 API 소비로 B-12 해소, 실-cli 계약 테스트 + `cli_version` 단언(B-13). → **경계 B**로 cli와 협의.
4. **성능** — `/api/posts` 뷰 오프로드(B-7), `/proc` liveness(B-8), last_query tail/캐시(B-9).
5. **위생·엣지** — SQLite busy_timeout(B-6), SSE 큐 bound(B-10), clone 심링크(B-11), Caddy auth 단일소스(B-5), 버전/CHANGELOG.
